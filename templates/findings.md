# Findings 模板

> 适用于所有产出 finding 的 Agent：`redteam` / `review` / `critic` / `acceptor` / 审查类执行 Agent。
> 纪律来源：`docs/spec/evidence-discipline.md`。

## 元信息

```
agent: 
run_id: 
审查范围: 
审查时间: 
结论摘要: 高X条 / 中Y条 / 低Z条 / 待验证W条
```

## 高危

### H1 [类别·高·置信度] 一句话标题

- **位置**：`file:line`（多位置分开列）
- **证据**：
  ```
  <真实原文，≥3 行，带上下文。不许转述。>
  ```
- **复现**：<具体操作序列 / 输入→结果 / 触发条件解剖>
- **影响**：<用户可见后果 / 数据后果>
- **修法**：<1–3 句>

## 待验证区

> 无法静态证实、需运行期验证的假设。**必须单独成区，不得混入主清单。**

- <假设> —— 验证方法：<...>

## 豁免挑战

> 认为豁免清单有错的，列证据。

## 范围外发现

> 不属于本域但值得记录的，标注建议归属。同时登记进 `tasks/dev-findings.md`。

## 覆盖声明（强制）

```
- 我实际读了哪些文件：<完整清单>
- 我做了哪些检查：<逐项>
- 我没做什么：<诚实申报>
- 我无法核实的部分：<原因>
```

---

## 类别取值

`bug` / `logic` / `data` / `ux` / `quality` / `security` / `perf` / `deadcode` / `schema` / `docs`

## 置信度取值

`[确定]` / `[高]` / `[中]` / `[待验证]`

## 最容易犯的三个错

1. **转述代替引用** —— 读者无法判断你是不是编的。
2. **把 `[待验证]` 混进主清单** —— 虚报。
3. **覆盖声明写「已全面审查」** —— 没有清单的宣称等于没说。
