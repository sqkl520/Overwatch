# 输出格式

> 默认 ADHD 友好。用户说「关掉 ADHD 模式」后切换为常规叙述。

## 1. 七条硬规则

1. **首行即行动或状态** —— 第一句话是「现在是什么阶段 / 你需要做什么 / 结论是什么」，不写铺垫。
2. **编号步骤** —— 涉及操作时用 1/2/3，不用段落。
3. **每轮复述进度** —— 用一行状态保持用户的定位感。
4. **零客套** —— 不写「好问题」「希望这对你有帮助」「让我来帮你」。
5. **列表不超过 5 条** —— 超出则分组，分组标题本身不超过 3 个字。
6. **错误只陈述事实** —— 「验收不通过：第 2 项标准缺少来源引用」，不写「很抱歉」。
7. **收尾给一个明确的下一步** —— 用户看完知道该点哪里、说什么、等什么。

## 2. 状态行

> **⚠ 这一节描述的是约定，不是已实现的能力。** 仓库里**没有任何脚本输出这个格式**：
> `scan-sessions.mjs` 打印的是会话表（见 `docs/GUIDE.md` §4），不是逐 Agent 状态行。
> 状态行的字段名与语法可由主线程按下面写，但**数字必须来自 `scan-sessions.mjs --json`**，
> 不得由模型估算。真要自动化，得先写一个渲染器——现在没有。

约定格式：

```
[阶段B · Agent#3 EXPLORING · reads=42/novelty=0.74/hb=14s · no_write=4m · budget=est:31% · liveness=reconstructed]
```

字段定义见 `docs/spec/state-model.md` §8。**数字只能来自 `scan-sessions.mjs --json` 的对应字段，不手写。**

### 2.1 为什么数字必须来自脚本

手写的状态行会随模型心情变化：数字编得越来越像真的，但没有任何计算支撑。这比没有状态行更坏——它自带格式可信度，用户无法区分真假。

任何字段无法计算时写 `unknown`，**不允许估算出一个看起来精确的数**。

### 2.2 多 Agent 时的排布

```
[阶段B · Agent#3 EXPLORING · reads=42 novelty=0.74 hb=14s · budget=est:31%]
[阶段B · Agent#5 PRODUCING · edits=6 · last_hb=12s]
[阶段B · Agent#7 STALLED · probe=LOOPING · 重复读 pkg.json×4 · 已L3注入(deferred)]
[阶段B · Agent#9 BLOCKED · host-reported-blocked · 等：权限确认 · 重跑 0/0]
```

超过 5 个 Agent 时只列异常（`STALLED` / `FAILED`），正常的合并为一行：`[其他 4 个 EXPLORING/PRODUCING 正常]`。

## 3. 阶段汇报节奏

默认**只在阶段边界汇报**：Phase A 开始、Phase A 完成、Phase B 派发、Phase B 全部返回、Phase C 冲突登记、Phase E 验收结论。

用户说「每个 Agent 返回都汇报」时切换为逐条汇报，但每条不超过 3 行。

## 4. 失败报告

验收连续 3 轮不通过时提交。**不假装通过。**

```markdown
# 失败报告：<run-id>

## 结论
3 轮修复后仍未通过。剩余 N 项标准未满足。

## 每轮改了什么
| 轮 | 修复动作 | 仍未通过的标准 | 为什么没解决 |
|---|---|---|---|
| 1 | ... | AC2 | ... |
| 2 | ... | AC2 | ... |
| 3 | ... | AC2 | ... |

## 剩余问题需要什么外部条件
- AC2：需要 <具体条件>，当前无法获得，因为 <原因>

## 建议
<停止 / 换策略 / 降低标准（需用户批准）>
```

## 5. 冲突登记格式

Phase C 的冲突汇总：

```
## 一致
- <结论>：<哪些 Agent 同意>

## 分歧
- D1：<A 说 X，B 说 Y>
  → 已派 Resolution Agent
  → 裁决：<结论> / 悬置（需要 <证据>）

## 互补
- <A 的结论> + <B 的结论> = <合并后更强的结论>
```

**禁止静默共识**：多个 Agent 给出相同结论时，必须至少有一个 Agent 被明确要求寻找反面证据。找不到反面证据**不等于**结论正确，只等于「当前轮次未发现反例」，必须在报告中如实标注。

## 6. 常规模式（ADHD 关闭后）

用户说「关掉 ADHD 模式」时：

- 可以用段落叙述；
- 状态行降为每 3 轮一次；
- 步骤可以写成散文，不强制编号；
- 仍然保留：零客套、错误只陈述事实、收尾给下一步。

**不随模式改变的**：证据纪律、四件套、覆盖声明。那些不是输出风格，是正确性要求。
