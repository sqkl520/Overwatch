# ADR-0002：对规格中不可执行的判据做「诚实降级」

- 状态：**Proposed**（待用户批准；批准前 `docs/spec/*` 中与本文冲突的条目以本文为准）
- 日期：2026-10-29
- 决策者：sqcola
- 相关：ADR-0001（为什么是纯配置库）

## 背景

原始规格（`docs/spec/` 的上游 `OmniSight` 设计稿）定义了可执行的判据。但那些判据写于「存在运行时守护进程」的假设之下。本仓库是纯 Claude Code 配置库，没有常驻进程。在落盘前，我们**实测**了这些判据在真实轨迹上的表现。

样本：本机 `~/.claude/projects/` 下 **2021 个 transcript 文件**、**239,549 次 tool_use**、**237,567 个相邻调用间隔**（实测于 2026-10-30；数字随会话增长会变，比例稳定）。

## 实测结果

### 1. 心跳阈值 180 秒会大面积误判

| 指标 | 实测值 |
|---|---|
| 至少出现一次 >180s 间隔的会话 | **1275 / 2021 = 63.1%** |
| 全部间隔中 >180s 的比例 | **9.72%** |
| 间隔分位数 | p50 = 14s，p90 = 174s，**p99 = 1444s** |

规格 §5.2 写「心跳间隔 > 3 分钟 → 判定进程异常，进 FAILED」。按此执行，**六成以上的会话会被判失败至少一次**。长间隔的主要成因不是进程死掉，而是权限确认弹窗在等人、用户中途离开、依赖下载。结果是规格 §5 开篇自称要消灭的「误判 → 全量重跑 → 再误判」死循环，只是换了个触发源。

**决策**：阈值改为**会话自适应**。取该会话自身间隔分布的 p95（下限 120s、上限 900s），而不是全局固定 180s。冷启动（间隔样本 < 20）时不下 FAILED 判定，只标 `liveness: insufficient-sample`。

### 2. novelty 公式排除了六成以上的工具

规格 §5.2 定义：

```
novelty = 新 (file_path, offset, limit, pattern) 组合数 / 窗口内调用数
```

但真实工具分布是：

| 工具 | 占比 |
|---|---|
| Bash | **62.3%** |
| Read | 15.0% |
| Edit | 10.4% |
| Grep | 5.9% |
| Write | 2.0% |
| Agent | 1.5% |
| Glob | 0.7% |

Bash 的入参是 `{command, description}`，**没有** `file_path/offset/limit/pattern`。按其签名，所有 Bash 调用的签名恒等，分子恒为 0，novelty 恒为 0 → 连续 3 窗口 <0.2 → 正常跑 `mvn`/`git`/`node` 的 Agent 被判 `STALLED`。

**决策**：novelty 改为**按工具类型分签名**，见 `docs/spec/state-model.md` §3。每种工具贡献一个归一化到 `[0,1]` 的新颖度增量，再加权平均。权重来自实测占比（Bash 0.62 / Read 0.15 / Edit 0.10 / 其余 0.13），使窗口内各工具的影响与真实频率成正比。

### 3. 四态集合不互斥

规格 §5.1 定义 `PRODUCING = 有 Write/Edit/Bash/最终交付物输出`。但 `ls`、`git status`、`grep`、`cat` **全部是 Bash**。于是任何只读探索都被判 `PRODUCING`，`EXPLORING` 只在「纯 Read、零 Bash」的会话里才可能出现。

后果链：纯探索 → 判 PRODUCING → 送验收 → 无交付物 → 不通过 → 修复 Agent 无输入 → 3 轮后提交失败报告。而 §5.1 同时规定「EXPLORING 严禁重跑」，两条规则组合后**没有任何路径能让纯探索型任务通过**。

**决策**：状态判定改为**有序互斥判定**（首个命中即返回），且 PRODUCING 的判据改为「产生了**持久化变更**」（Write/Edit 成功，或 Bash 命中写入类命令词表），而非「调用了某个工具」。见 `docs/spec/state-model.md` §2。

### 4. 会话注入对运行中的会话失效

`claude --help` 中 `--bg --resume <session-id>` 的原文：

> continues that session in the background under the same ID, **or starts a copy and says so when the session is already running**

即：目标会话**正在运行**时，注入落到副本上，用户窗口里不会出现任何东西。规格 §10 Phase F 第 6 步「由主线程执行注入」在运行中会话上不成立，第 7 步「该对话重新纳入监控」监控的是一个已经分叉的新会话。

**未验证项**（诚实标注）：本机 `claude -p` 在非交互环境返回 `Not logged in`，因此**未能实测**注入语义。上述结论仅来自 `--help` 文本与另一独立 Agent 的实读。若 CLI 登录后行为不同，本条需重新评估。

**决策**：`relay` 的默认模式为 `manual` —— Relay Agent 产出草稿，由用户复制发送。`host` 模式（宿主支持注入时）保留接口但不作为默认。**这使本库无法独立满足规格 §1「会话写入不可降级」的要求**，必须在 README 顶部声明。

### 5. 规格自身矛盾

| 位置 | 原文 |
|---|---|
| §1 第 25 行 | 「会话写入/注入……**核心能力，不可降级**；若无此能力则系统不成立」 |
| §9 第 282 行 | 「缺少"会话写入" → 降级为"接力草稿生成器" `relay: manual`」 |

同一份规格对同一能力给出互斥结论，实施者按任一条都能自证合规，验收 Agent 无法用预声明标准判定。

**决策**：以 §9 为准（降级可行），并在 README 与 `docs/spec/relay-protocol.md` 顶部明确写出能力边界。**不假装 §1 仍然成立。**

## 未采纳的反例（经核实不成立）

- **「派生树活性无法离线计算」**：不成立。实测子 Agent transcript 独立成文件（`<session>/subagents/agent-<id>.jsonl`），配套 `.meta.json` 含 `toolUseId` 指回父会话的 Agent 调用与 `spawnDepth`。父子可重建，派生树活性可算。详见 `docs/spec/state-model.md` §5。
- **「`init.defaultbranch=master` 会让仓库默认分支错误」**：已规避，`git init -b main`。

## 代价

- 本库做不到「全自动接力」。用户仍需亲手发送草稿。
- 四态判定靠主线程按 skill 执行，**没有强制力**：主线程可以自称 PRODUCING 绕过。这是 ADR-0001 的固有代价。
- novelty 权重来自单机样本（2021 个 transcript），换环境可能需要重估。

## 什么时候该反悔

出现以下任一信号，应升级为 ADR-0001 中描述的运行时形态：

1. 宿主提供对**运行中**会话的稳定注入接口；
2. 需要同时监控 10 个以上会话（主线程轮询不可行）；
3. 四态误判率被证明无法靠规则收敛（需要可回放的事件流来定位）。
