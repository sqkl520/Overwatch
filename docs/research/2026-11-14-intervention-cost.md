## 一、口径（先读这一节，其余全部由它推出）

### 1.1 被测量的假设（用户原话）

```
有提问的中断：「这里按 A 还是 B」        ← 一句话解决
没提问的中断：「你完全理解错了，重做」   ← 代价是一次返工
```

上一轮（`2026-11-14-execution-phase-measurement.md`）测的是中断**次数**，
结论是控制体量后「开工前提问」没有优势。**次数相同不代表代价相同**，
所以这一轮测代价。

### 1.2 复用上一轮的口径，不重造

分组 A/B/C、执行起点、执行期、人类发言判据**全部直接沿用**：

- `isWriteCall` / `normToolName` 从 `measure-execution-phase.mjs` import；
- 官方分组与官方「执行期工具数」直接调它的 `run()` 拿，**不自己重算**；
- 本脚本只自算一遍分组用于**对账**：实测 `分组不一致 0 个、中断数不一致 0 个`。

### 1.3 主指标：返工需求率

```
返工需求     = 执行期人类发言里含否定/撤销/重做语义的那几条
返工需求率   = 返工需求数 ÷ 执行期中断数
```

判据**复用** `measure-interventions.mjs` 的 `classifyHumanMessage()` 返回 `correction` 的那一档
（正则含「不对 / 改回 / 撤销 / 重做 / 理解错 / 撤回」等），不另写一份。

**为什么选它，而不是用户列的那四个候选** —— 见 §3。一句话：
它是唯一在**语义上就等于返工**的信号，不依赖「某个工具痕迹与返工相关」这个未经验证的假设。
代价是召回率低（用户也可能用不带否定词的话表达不满），宁可低估，不猜。

**它天然免疫任务体量**：分子分母都是**中断级**，不是工具级。所以它是控制体量的首选比较。

辅助指标两个，都保留：

- **每 100 次执行期工具的返工需求数**（体量敏感的密度口径）；
- **自撤销事件**（工具痕迹：`Write` 覆盖本会话已写过的路径，或 `Edit` 恢复本会话此前删掉的文本）。

### 1.4 去重：两层，**第二层是本次新增，且改变了结论的分组人数**

```
426 份落盘
  ↓ 第一层（沿用 measure-execution-phase.run()）：同 sessionId 去重 + 整份内容哈希
     丢弃 108（同 sessionId）+ 106（fork 重放）
  ↓ 第二层（本次新增）：恢复分支快照
     合并 66 份，涉及 25 簇
最终 247 个会话：A 7 / B 34 / C 85 / none 121
```

**为什么需要第二层。** 第一层按「整份内容哈希 + 记录条数」判重。但实测存在一类它抓不到的簇：
**同一段对话被写成多个 sessionId，前缀逐条相同（连时间戳都相同），长度不同**——
短的那份是一路恢复出来的早期快照。

最刺眼的一簇（A 组）：

| sessionId | 归一化记录数 | 与最长者的公共前缀 | 时间戳是否逐条相同 |
|---|---|---|---|
| `2b8b5fc6` | 2766 | — （基准） | — |
| `69a23385` | 2325 | 2322 条（99.9%） | 全部相同 |
| `b7deae45` | 473 | 471 条（99.6%） | 全部相同 |

**三份全被判进 A 组，而 A 组总共只有 14 个。** 不去重等于把同一段对话数了 2~3 遍，
而这段对话恰好是 A 组里 undo 最多的一个（17 次）——它一被重复计数，
「A 组 undo 密度高」这个观察就被放大了。

**判据**（`dedupeResumeForks`）：候选集 = 同 `firstTs` 且首条人类消息相同；
在此之上要求**归一化记录序列的公共前缀 ≥ 较短者的 98% 且 ≥ 30 条**。
同簇只保留最长的一份。

**为什么不是别的键**：

- 只用「首条人类消息相同」→ 会把同一句开场白之后各干各的真实会话并掉；
- 只用「公共前缀」→ 同上，开头相同但后面分叉的会被误并；
- 两个条件**同时**要求才安全：前缀够长**且**前缀占较短者的比例够高，说明短的那份**就是**长的前缀。

**这条规则是可复算的**，并在测试里锁了四个方向：并（真前缀）、不并（开头相同但后面各自很长）、
不并（前缀短于 30 条）、不跨 `firstTs` 并。

### 1.5 一条必须写明的诚实边界

第二层去重**改变了分组人数**（A 14 → 7）。这意味着上一轮报告里的 A=14 里
**有 7 个是同一段对话的副本**。那条结论（「A 的中断原始值低于 B，但控制体量后不成立」）
的**方向**不受影响——本文 §4 用去重前的数据复核，结论方向一致。
但**任何引用 A=14 的具体数字都必须重算**。

## 二、直接回答

### 2.1 控制体量后，「开工前问」的代价是不是更低？

**不是。A 的代价在每一个控制体量的口径下都不低于 B。**

| 口径 | A（n=7） | B（n=34） | 差 |
|---|---|---|---|
| 返工需求率（主指标，中断级） | **1.20%** | **0.99%** | A 高 0.21 个百分点 |
| 每 100 次工具返工需求 | **0.035** | **0.019** | A 高 1.8 倍 |
| 自撤销密度（每 100 工具） | 0.650 | 0.302 | A 高 2.1 倍 |
| 自撤销（每会话 median） | 3.0 | 3.5 | B 略高 |

置换检验（5000 次，固定种子）：**均值差 p = 0.693，中位数 p = 1.000，
Cliff's delta = +0.109**（>0 表示 A 的代价更大）。

**三项检验的方向一致，都不支持「开工前问代价更低」。**

### 2.2 分层与匹配（控制任务体量的两种做法）

**按执行期工具数四分位分层**（返工需求率 / n）：

| 层 | A | B | C |
|---|---|---|---|
| 工具 ≤ 2 | — (0) | — (0) | 0.00% (32) |
| 2 < 工具 ≤ 286 | 0.00% (2) | 0.00% (1) | 0.00% (28) |
| 286 < 工具 ≤ 1024 | **2.44%** (3) | 1.55% (14) | 0.00% (14) |
| 工具 > 1024 | **0.88%** (2) | 0.61% (19) | 0.86% (11) |

**在唯一有可比样本量的两层里（各 3+14 与 2+19），A 都高于 B。**

**体量 1:1 匹配**（容差 log 比 ≤ 0.7，5 对）：

```
A 50ec242b 工具 2612 返工 1 ｜ B 93a8f44d 工具 2515 返工 0   → A 多 1
A 356e31e9 工具 1479 返工 0 ｜ B 79f9072c 工具 1466 返工 0   → 平
A 2b8b5fc6 工具  639 返工 1 ｜ B af6779f8 工具  647 返工 0   → A 多 1
A 9aa577ef 工具  393 返工 0 ｜ B ea338c0e 工具  392 返工 0   → 平
A 3f0f6fac 工具  288 返工 0 ｜ B 910e505f 工具  378 返工 0   → 平
```

**A 返工更少 0 对，B 返工更少 2 对，打平 3 对。** A mean 0.4 / B mean 0.0。

### 2.3 样本够吗？

**不够，而且这是本次最硬的限制。** 必须如实说：

- **A 组 n=7**，返工需求**总共只发生 2 次**（`50ec242b`、`2b8b5fc6` 各 1 次）。
- **B 组 n=34**，返工需求总共 11 次。
- **全语料可比会话 126 个、执行期中断 1727 次，返工需求只有 15 次（0.87%）。**

一个只有 15 个事件的主指标，做置换检验的 p 值**本身也不可信**。
上表的 p = 0.69 只能读成「**没有证据支持 A 更低**」，
**不能**读成「A 与 B 相同」或「A 更高」。**这是两个不同的结论，本文只支持前者。**

### 2.4 如果不是，那用户「提问减少返工」这个假设呢？

**在这批语料上，它没有数据支持——如实说。**

必须同时说清两件事，否则就是选择性陈述：

1. **不是「被证伪」。** 样本太小（15 个事件）检验不出中等效应。
   A 组只有 7 个会话、2 次返工，任何方向的结论都撑不住。
2. **也不是「被支持」。** 原始值、每百工具密度、分层、1:1 匹配，
   四条口径没有一条显示 A 更低。

**所以准确的说法是：本语料无法回答这个问题，因为返工事件太稀疏；
而在能观察到的那点信号里，方向与假设相反。**

## 三、为什么主指标不是用户列的那四个候选

这一节是本次最重要的方法结论。四个候选我**全部实测**了，三个不能用。

### 3.1 候选 (a)(b) 文件重叠 / 重做范围 —— **方向是反的**

直觉：中断前后写同一批文件 = 返工。
实测：**真实中断点后的重叠率 32.4%，同长度随机窗口 42.0%。中断点更低。**

```
中断后 10 个写操作落在「中断前已写过的文件」上的比例
  真实中断点   32.38%（5062/15631，1628 个窗口）
  随机切点     42.03%（1491 个窗口，同一会话内、不跨人类发言、同长度）
```

原因很朴素：**用户停下来说话时，AI 通常正在一个文件上连续工作**；中断后它继续改的还是
那个文件。而随机窗口横跨整个会话，覆盖面更大。**「重叠」测的是工作连续性，不是返工。**
这个否定结论已固化进脚本（`redoShareAfterInterruptions` + `redoShareRandomWindows`），**可复算**。

### 3.2 候选 (c) 中断后 AI 首轮输出长度 —— **无差别**

实测（定性抽样，未进最终脚本）：真实中断后首轮 AI 文本 mean 238 字符，
随机切点 253 字符。**几乎没差**，且方向也是反的（中断后更短）。

### 3.3 候选 (a') 自撤销事件 —— **能测到一点，但很弱**

`Write` 覆盖本会话已写过的路径 / `Edit` 恢复本会话此前删掉的文本。这是**可判定**的硬信号。

中断点前后各取 10 个写操作对比：

```
中断后  2.69%（424/15761）
中断前  2.23%（355/15892）
比值    1.20
```

**只高 20%。** 它确实捕捉到一点「中断后更容易撤销」，但不足以当主指标——
它测的是「AI 事后改了之前写过的东西」，而**正常迭代也会这样**。
更适合当辅助指标，本文就是这么用的。

### 3.4 主指标：返工需求率

唯一在**语义上**就等于「返工」的信号。代价是召回率低：语料里 1727 次中断，
只有 15 次带明确的否定/撤销语义（0.87%）。

### 3.5 还有一个更根本的发现：**中断绝大多数不是返工**

这是本次最该被记住的一张表：

| 组 | 中断数 | 纠正 | 催促 | 其它 | 纠正占比 |
|---|---|---|---|---|---|
| A 开工前 | 166 | **2** | 18 | 146 | **1.20%** |
| B 开工后 | 1109 | **11** | 210 | 888 | **0.99%** |
| C 从不问 | 452 | **2** | 105 | 345 | **0.44%** |

**全语料 1727 次执行期中断里，只有 15 次（0.87%）是纠正。**
最大的一块是「其它」（1379 次）——抽样看内容，绝大多数是**新增需求、补充前提、
报告现象、问进展**，不是「你做错了」。

**这直接解释了为什么上一轮「按次数测」得不出提问的优势，本轮「按代价测」也测不出来：
在这批语料里，「中断 = 返工」这个前提本身就不成立。**
用户举的「你完全理解错了，重做」在真实数据里是**万分之一量级的事件**，
不是中断的典型形态。

## 四、稳健性：去重前 vs 去重后

第二层去重会改变人数，所以两组数字都必须给，读者自己能看出结论方向是否稳定。

| 口径 | 去重前（A=14 / B=38） | 去重后（A=7 / B=34） |
|---|---|---|
| A 返工需求率 | 1.49% | 1.20% |
| B 返工需求率 | 0.93% | 0.99% |
| A vs B 均值 p | 0.561 | 0.693 |
| Cliff's delta | +0.068 | +0.109 |
| A 每 100 工具返工 | 0.045 | 0.035 |
| B 每 100 工具返工 | 0.018 | 0.019 |
| A 自撤销密度 | 0.813 | 0.650 |
| B 自撤销密度 | 0.302 | 0.302 |

**方向完全一致：A 的返工需求率、返工密度、自撤销密度都高于 B，p 值都远大于 0.05。**
去重只是把小样本的数字挪了挪，**没有改变任何一条结论的方向**。

## 五、体量相关（本轮承重墙）

```
Spearman(工具数, 中断数)     = 0.903   ← 中断次数基本上是任务体量的函数
Spearman(工具数, 返工需求)   = 0.312   ← 返工需求和体量只有弱相关
Spearman(工具数, 自撤销)     = 0.748   ← 自撤销和体量强相关
控制体量后 中断数 vs 返工需求 的偏相关 = 0.298
```

**这张表本身就是本轮的主要收获：**

- **中断次数被体量解释 90%** —— 与上一轮一致，再次确认「按次数比」测的是体量。
- **返工需求只被体量解释 31%** —— 它**不是**体量的另一种说法，所以用它做对比有意义。
- **自撤销被体量解释 75%** —— 所以它不能单独当主指标：大任务自然改得多。
- **扣掉体量后，中断数与返工需求还有 0.30 的相关** —— 说明「被打断得多」与
  「返工多」不是同一件事。这与 §3.5 的结论一致：中断绝大多数不是返工。

## 六、我算不出来的（不许当结论用）

1. **「该不该返工」没有 oracle。** 我能数「用户说了几次重做」，数不出
   「这次改动本来就该被推翻」。用户心愿里的「需求传不准」这层因果，本机数据测不出。
2. **返工事件太稀疏。** 1727 次中断里 15 次返工。任何 A/B 对比都无法排除中等效应。
   A 组 2 次返工、7 个会话——**这个样本量下 p 值本身不可信**（报告 §2.3）。
3. **召回率未知。** 主指标只认带否定词的短消息（≤600 字符）。
   用户可能用「再看看」「我觉得有点怪」表达不满，这些**数不到**。
   所以本指标是**下界**，不是全量。
4. **Bash 写入不参与自撤销判定。** 本语料的写操作里 `Write`+`Edit` 占 82.2%
   （18494/22486），Bash 写入的路径无法可靠定位（见 `2026-11-13-bash-write-detection.md`）。
   自撤销指标因此只覆盖 82% 的写操作，**会低估**。
5. **第二层去重的阈值（98% / 30 条）不是实测最优。** 它是按「真前缀 vs 假前缀」的
   分布选的保守值。实测按不同阈值分组人数的变化：0.95 → A 7，0.98 → A 7，0.99 → A 7，
   在 A 组上稳定；但**没有 oracle 能证明某一份具体文件该不该并**。
6. **fork / 恢复分支的成因仍然不知道。** 我知道它们存在、知道怎么识别，
   不知道宿主为什么产生它们。
