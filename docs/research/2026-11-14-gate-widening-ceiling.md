## 0. 结论先行

1. **单因素消融里，唯一真正起作用的是 `+C`（结构性探索）与 `+B2`（宽松子 agent）**，分别消掉 12 与 10 个会话；`+B`（严格子 agent）消掉 5 个；`+A`（续接上游）**没有可靠的归属依据**，唯一前序档消掉 0 个。
2. **`+D`（修 `head -n 20`）不是扩宽，是收紧。** 它把 would-deny 从 27 抬到 28，并且**打穿了一个原本放行的会话**（`be6b89cf`：4 → 2）。原因是原实现把 `600` / `400`（来自 `head -c 400`、`head -c 600`）当成了"读过的文件"——那两条是**假路径**。把它算作"改宽"是口径错误。
3. **全开（`+D +C +B +B2 +A-greedy`）后真实项目 would-deny = 3 / 136（2.2%）**，比基线少 24 个。
4. **这 3 个里没有一个能确认"真没读过任何东西"**：
   - `aed8ec22`、`ea338c0e` —— 首写前 `Read pom.xml` → `Edit pom.xml`，**读的就是要改的那个文件**，真误伤；
   - `536cf97b` —— 首写前 4 次 `Agent` 调用，但子 agent transcript 目录为空（0 份），**证据缺失**，无法证实也无法证伪。
5. **没有任何扩宽把闸门削到恒真。** 阴性对照（69 个沙箱会话）在**每一个**扩宽下拦截数都是 50，一个都没掉。唯一掉到 0 的是"阈值降到 0"——那确实是被架空，而且一眼可见。
6. **替代方案里，阈值降到 1 最划算**：真实项目 27 → 13，沙箱只掉 51 → 49（掉的那 2 个是真的读够了才写）。

## 1. 装置与方法

### 1.1 为什么是"单因素消融"

每个扩宽**单独**打开、其余关闭。叠加着测会让后开的那个吃掉前一个的功劳，数字无法归因。全开单独测一次，作为上界。

### 1.2 沿用既有口径，不自创第二套

`analyzeOne()` / `dedupeForks()` / `isSandbox()` / `gateReadsOf()` / `tailGateReads()` 全部**直接 import** `observe-reality-check.mjs`，不复制实现。沙箱分桶就是那条既有规则：**路径含 `Temp\` 或 `.tmp-analysis`**。

两处必须自己重写，理由写在这里：

| 自己实现的 | 为什么不能复用 |
|---|---|
| `windowReadPaths()` | 要能**换解析器**（修缺陷前 / 后），`tailGateReads()` 把解析器写死在里面。窗口截断逻辑逐字节照抄，并用 `parserEquivalence()` 逐会话验证一致 |
| `subagentPathSet()` / `looseSubagentPathSet()` | 既有实现只返回**计数**，扩宽需要**路径集合**才能做并集 |

### 1.3 `+A` 怎么算：先说清它不可归属

任务书假设"续接会话上游读"是可以打开的一个维度。**实测它不是。**

| 事实 | 实测值 |
|---|---|
| 续接会话（首条人类消息是压缩摘要） | 69 |
| 其中有写 | 63 |
| 这 63 个里，**本文件仍保留压缩前的 tool_use 记录** | **0** |
| `compactSummary.parentUuid` 能唯一解析到同目录兄弟 transcript | 12 |
| 解析到多个（有歧义） | 54 |
| 解析不到 | 3 |

**63/63 个有写续接会话的 `preCompact = 0`** —— transcript 在压缩点被重写，历史根本不在盘上。所以 `+A` 只能退化成"猜哪个兄弟文件是前序"。

本文因此给两个数，**分开命名，绝不混报**：

- `+A-unique`：只认唯一前序（`lastTs ≤ firstTs` 且同 cwd 的候选恰好 1 个）。**可称归属**。
- `+A-greedy`：多个候选时取最近 3 个的并集。**归属不成立，只作上界**。

> 本文所有"全开"用的是 `+A-greedy`，因为它才是对闸门**最有利**的假设。若按 `+A-unique` 算，全开是 4 个而不是 3 个。

### 3.2 全开后 `D-no-evidence` 有几个

**3 个，就是上面这 3 个全部。** 基线时 `D-no-evidence` 也是 3 个（`aed8ec22` / `ea338c0e` / `536cf97b`）——**扩宽一个都没能动到 D 类**，因为 D 类的定义就是"没有任何可反驳的证据"，扩宽只能增加证据来源，不能凭空造出证据。

### 3.3 全开 vs 不装：一句话量化

> **全开之后，闸门只拦 3 个真实会话（136 个里的 2.2%），其中 2 个是"读了目标文件本身"的真误伤、1 个是"证据不在盘上"的无法证实——确认真没读的是 0 个。它唯一还在正确拦截的是沙箱桶里的 51 个，而那 69 个会话的 prompt 就是"写个文件然后停"，不是真实工作。**

## 4. 替代方案（同一装置）

| 方案 | 真实 would-deny | 占比 | 沙箱拦截 | 是否被架空 | 备注 |
|---|---|---|---|---|---|
| 阈值 0 | 0 | 0.0% | **0 / 69** | **是** | 恒真，闸门等于不存在 |
| **阈值 1** | **13** | **9.6%** | **49 / 69** | 否 | 沙箱只掉 2 个（51 → 49） |
| 阈值 2 | 22 | 16.2% | 51 / 69 | 否 | 沙箱一个不掉 |
| 阈值 3（当前） | 27 | 19.9% | 51 / 69 | 否 | — |
| 阈值 5 | 52 | 38.2% | 68 / 69 | 否 | 明显过严 |
| **替代 3：读过目标文件即放行** | **23** | **16.9%** | **51 / 69** | 否 | 见 §4.2 |

### 4.1 阈值降到 1 / 2 的读法

阈值 1 把真实项目从 27 降到 13（消掉 14 个），沙箱只从 51 掉到 49。**掉的那 2 个沙箱会话是真的读了 ≥1 个文件才写的**——也就是说这 2 个本来就该放行，闸门拦住它们是错的。这是"降阈值"里唯一被实测支持的一档。

阈值 0 把沙箱也清零了，**这是"削弱到恒真"的教科书样本**：它连"写个文件然后停"都不拦了。

### 4.2 替代 3：读过目标文件本身即放行

**可实现。** `decide()` 拿得到 `file_path`：`writeIntentOf()` 里 `intent.paths` 就是从 `ti.file_path` / `notebook_path` / `path` / `target_file` 取的，`decide()` 里已经有 `log.paths = intent.paths.slice(0, 5)`。判据改成"`intent.paths` 的任一项 ∈ 已读路径集合"即可，不需要新的输入。

实测（阈值 3 + 目标文件豁免）：

| 指标 | 值 |
|---|---|
| 放行 | 113 / 136 |
| 仍拦 | **23 / 136（16.9%）** |
| 首写前读过目标文件本身的会话 | 20 / 136 |
| 目标只在累计/子agent/上游读到、窗口里没有的 | 2 |
| 沙箱仍拦 | **51 / 69（没被架空）** |

它比基线的 27 少 4 个，那 4 个正是 `aed8ec22`、`ea338c0e`、`910e505f`、`3e58c93b`——**全都确实读过自己即将写的那个文件**。所以这一条能精确打掉"读了目标文件却因为只读了 1 个而被拦"这一整类误伤，而且**沙箱一个都没掉**。

## 5. 阴性对照：没有任何扩宽把闸门削到恒真

69 个沙箱会话（prompt 就是"写个文件然后停"）在**每一种扩宽下拦截数都是 50**：

| 变体 | 沙箱拦截 |
|---|---|
| 原样 / `+D` / `+C` / `+B` / `+B2` / `+A-unique` / `+A-greedy` / 全开 | **51 / 69（全部相同）** |
| 阈值 1 | 49 / 69 |
| 阈值 0 | **0 / 69 ← 唯一被架空的** |

**这个桶是识别"削弱到恒真"的唯一硬指标。** 所有判据类扩宽都不动它，因为沙箱会话本来就没有 `Read`、没有 `Agent`、没有结构性探索、没有上游——扩宽的任何一条都够不着它们。**这反过来说明：扩宽在真实项目上的收益全部来自"闸门看不见的地方"，不是来自"闸门变松了"。**

## 7. 数字口径自检

### 7.1 主断言：与参考实现在**同一次运行**里逐项比

脚本里 `main()` 会 import `observe-reality-check.mjs` 的 `buildReport()` 并当场比对 12 项。**不拿写死的常数当基准** —— 实测在写这份脚本的两小时内，沙箱会话从 66 长到 69（本机又跑了一次 e2e），写死的 66/49 会当场变红，而红的原因不是复现错了，是语料长了。那种"断言"只会训练人忽略红灯。

最近一次实跑（439 份 transcript）：

```
✓ 真实项目有写会话           参考 136  实测 136
✓ 真实项目 would-deny        参考  27  实测  27
✓ 真实项目 读 0 个           参考  13  实测  13
✓ 沙箱有写会话               参考  69  实测  69
✓ 沙箱 would-deny            参考  51  实测  51
✓ 归因 A/B/B2/C/D            参考 5/5/8/6/3  实测 5/5/8/6/3
✓ cumulative would-deny      参考  26  实测  26
✓ broad would-deny           参考  15  实测  15
```

任务书给的是 27/136、13/136、49/66。**真实项目三项逐项相同**；沙箱从 66/49 变成 69/51，是语料生长（快照漂移单独打印，不判失败）。

### 7.2 第二层：解析器等价性

`windowReadPaths(fixed=false)` 与 `tailGateReads()` 在 **205 个有写会话**上逐会话比路径集合，**不一致 0 个**。这条保证"我重写的窗口读取和闸门本体是同一口径"，否则 §2 里 `+D` 那个 27 → 28 的变化可能只是窗口差异造成的假象。

### 7.3 负向验证（把缺陷放回去，必须变红；四条全部实跑并已恢复）

| 把什么改坏 | 期望 | 实测 |
|---|---|---|
| `parserEquivalence` 去掉 `checked > 0` 条件 | 空集合上恒真通过 | **fail 2** |
| `+D` 的 `shortValueFlag` 置 `null`（退化成原缺陷） | `head -n 20` 测试红 | **fail 4** |
| `contentReads()` 把结构性探索也算作内容读 | `structOnly` 判定红 | **fail 2** |

## 8. 诚实边界

1. **`+A` 的两个数都不能当"归属"用。** 63/63 个有写续接会话的压缩前记录不在盘上，`parentUuid` 只有 12/69 唯一可解析。`+A-greedy` 取"最近 3 个候选的并集"是一个**对闸门最有利的假设**，不是证据。真正的修法是宿主在压缩点保留指针或保留历史，闸门自己做不到。
2. **"读过"仍然只是"读到过路径"。** 本报告全程没有校验"读懂了这个文件"。`aed8ec22` 读了 `pom.xml` 却编辑错了位置，这种事本装置测不出来，也不该声称能测。
3. **`broad` / `+C` 的证据强度弱于内容读。** 一次 `ls` 不等于读了内容。§2.2 那 3 个"结构性放行"就是这条边界的实例，已单列。
4. **沙箱分桶靠路径模式**（`Temp\` / `.tmp-analysis`）。若有真实项目恰好放在 `Temp` 下会被误分。实测语料里没有，但这是模式匹配，不是分类器。
5. **`+D` 的方向是"变严"，把它算作扩宽是错的。** 本文把它列进表里是为了给出完整消融，不代表它属于"改宽"。若只看"能降多少"，`+D` 的贡献是 **−1**（负的）。
