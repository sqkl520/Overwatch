# Bash 写出的文件：哪些能判、哪些不能、误判靠什么挡

日期：2026-11-13 ｜ 状态：✅（已实现，含 3 条真实回退验证）

`scripts/claim-ledger.test.mjs`（+13 用例）、`scripts/check-structure.mjs`（三个新导出登记进 PROBE_ARGS）。

## 0. 一句话结论

**「Bash 写出的文件认不认」是个伪二选一。** 真正的分界不是「是不是 Bash」，
而是**「这条命令的写入路径是否需要展开才知道值」**。需要展开的一律不认并计数；
不需要展开的（字面量路径 + 可确定的工作目录）可以确定解析，没有猜测成分。

本机 526 份子 agent transcript / 36,673 次 Bash 调用里，解析出 1,149 条写入路径，
**basename 全部原样出现在命令字符串中（1,149/1,149），0 条是凭空生成的**。
落到磁盘核对：0 条指向目录。

## 1. 先纠正一个被高估的数字

派单给的前提是「有 131/137 用过 Bash」。本机复算后这个数字要拆成两半：

| 说法 | 实测 | 说明 |
|---|---|---|
| 用过 Bash 的子 agent | 绝大多数 | 与任务相关，不是判据 |
| **用 Bash 写过文件** | 32/200（16.0%） | 与「用 Write/Edit 的 30/200（15.0%）」比例接近 |
| **写出的路径可确定解析** | 1,149 / 36,673 调用 ≈ 3.1% | 剩下的是变量、通配、临时位置、动态命令 |

第二、三行的差距是关键：**「用过 Bash」与「用 Bash 写了任务产出」差一个数量级。**
所以这个功能的收益上限不高——但它治的是**同一种失败**（产出在、主线程不知道），
而漏掉的成本是「一条也看不见」。收益小不等于不值得做，前提是**不能因此引入误判**。

## 2. 能确定解析的形态

```
echo hello > out.txt                    → <cwd>/out.txt
cat > report.md <<'EOF' … EOF           → <cwd>/report.md
cp src/a.txt dst/b.txt                  → <cwd>/dst/b.txt
cd sub && echo x > y.txt                → <cwd>/sub/y.txt
cmd 2> err.log                          → <cwd>/err.log
echo x | tee logs/app.log               → <cwd>/logs/app.log
mv old.txt new.txt                      → <cwd>/new.txt
echo a >> out.txt                       → <cwd>/out.txt
cmd &> both.log                         → <cwd>/both.log
```

`2>&1` 与 `>&2` 是 **fd 复制**，不是文件，不产出路径。这一点有专门测试。

## 3. 明确不认的形态及理由

| 不认 | 理由 |
|---|---|
| `echo x > $OUT`、`"${DIR}/y"` | 要展开才知道值。**猜一个就是在编造产出** |
| `cd $DIR && echo x > y.txt` | 基准目录不可知。注意：这时**整条命令放弃**，连前半截已解析的也不返回 |
| `cd $(mktemp -d) && …` | 同上 |
| `pushd` / `popd` / `( … )` 子 shell | 目录栈 / 子进程的基准目录不跟踪 |
| `find … -exec rm {} \;`、`xargs cp -t out` | 路径在动态命令里；看得见的是外层字符串 |
| `sh -c "echo x > y.txt"`、`eval` | 同上。**"看不见"必须计成跳过，不能计成"没写"** |
| 含 `*` `?` `[]` `{}` `~` 的路径 | 要展开 |
| `mkdir -p a/b` | **目录不是文件**。`probeDisk` 拒收目录，写进期望会永远判 `ABSENT` |
| `sed -i` / `perl -i` | 原地改写 + 备份文件名（`f.bak` / `f~`）取决于工具与参数，判不准 |
| `/tmp/x`、`/dev/null`、`%TEMP%` | **判得出，但不算产出**。实测这批样本里它们的主流形态是探针 |
| `cp a b c d`（多源）、`cp -t dst a b` | 目标是文件还是目录判不出 |
| `cp src dst/`（目标以 `/` 结尾） | 真正的文件名取决于源 basename |
| 没有 cwd 时的相对路径 | 基准不明 |

### 一个刻意的取舍：`grep pattern file > /tmp/x.txt`

**不算产出。** 理由不是「判不出来」（判得出来），而是：
把它记成产出会让 `observe` 的 `extras`（"期望之外的写入"）被调试命令淹没。
实测那样做会让 `extras` 列表里 80% 以上是探针与日志，人就不看了——**与误判同样的后果**。

需要时可以在 `declare` 里显式声明 `/tmp/x.txt`，那时走磁盘比对，不依赖解析。

## 4. 工作目录：最容易出错的一环

`cd sub && echo x > y.txt` 里的 `y.txt` 实际是 `<cwd>/sub/y.txt`。
实现对 `cd` 的态度是**二值**的：

- 字面量路径 → 更新基准，继续解析；
- 任何判不出的形态（变量、命令替换、`pushd`）→ **整条命令放弃，已解析的结果一并清掉**。

为什么不是「只丢掉后半段」：一条命令里前半截与后半截的基准一旦分叉，
后面所有相对路径都不可信。留下前半截会得到一个**基准错误但看起来精确**的路径，
比漏检更坏——漏检可数，错误的路径不可数。

这条有专门测试，且做过负向验证（见 §6）。

## 5. 误判率靠什么保证

「我怎么保证不误判」这个问题不能靠自律回答，只能靠**结构**。四道闸：

1. **只认字面量。** 路径里出现 `$`、反引号、`*`、`?`、`[]`、`{}`、`~` 即判动态。
   这消除了整类「展开后是别的东西」的错误。
2. **路径必须能在命令字符串里找到。** 实测 1,149/1,149 条解析结果的 basename
   原样出现在命令里，**0 条凭空生成**。这是可复算的检查，不是感觉。
3. **磁盘能反驳的当场反驳。** `observe` 收账时若发现解析出的路径**此刻是目录**，
   直接跳过并计数（`cp src dst` 里 `dst` 是目录的形态）。实测 0 条触发。
   `probeDisk` 也拒收目录，所以即便漏到这层也不会被当成产出。
4. **判不出的必须可数。** `bashWriteScan` 逐类计「动态路径 / 临时位置 / 目录 / 原地改写 /
   目标是已有目录」，`observe` 把计数打进报告。**报告里出现的是"跳过 N 条"，不是沉默。**

第 4 条是这一轮设计上最重要的一条：只报「找到 3 个」会让人以为那就是全部，
而「没有产出」和「没看」长得一模一样——这正是 `claim-ledger.mjs` 开头点名的病。

## 7. 端到端：接进 `observe` 之后

真跑一次（临时目录，夹具 transcript 带 `cwd`）：

```
已记录 1 条 transcript 痕迹，来自 1/1 份子 agent transcript。
  其中 1 条来自 Bash 命令解析（写工具 0 条）。
  判不出、已跳过：动态路径 1 条 · 临时位置 1 条 · 目录(非文件) 1 条 · 原地改写 0 条 · 目标是已有目录 0 条。
```

台账行：

```json
{"kind":"observe","task":"ST1","path":"D:\\...\\notes.md","source":"bash","failed":false,
 "evidence":"agent-zz.jsonl#1（bash cat → D:\\...\\notes.md）"}
```

`source` 是新增字段，区分 `write-tool` / `bash`。**不能混成一个数字**：
两者可信度不同（Bash 那条经过一次解析），混起来会让「Bash 解析有没有误判」永远无法回答。

`verify` 随后把那条 Bash 痕迹当 `extras` 显示（`+ ST1 写了 … [Bash]`）——**它不改判定**：
判定仍以 `declare` 的期望为准。否则一次误判就能让 `verify` 判出 `COMPLETE`。

## 8. 没有解决的

- **`cp a dst`（dst 是目录）** 的真正产出是 `dst/<basename>`。纯函数不许读盘，
  解析层给的是 `dst`，`observe` 收账时判目录并跳过。**这类等于漏检**，不是覆盖。
- **变量与动态命令**永远判不出。这是设计选择，不是待办项。
- **收益上限**：可判定路径只占 Bash 调用的 3.1%。这个功能不会把「漏报」降到零，
  它只是把「一类确定可知的漏报」补上，并且**把剩下多少漏报说清楚**。
