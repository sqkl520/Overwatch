## 一、先回答：旧指标错在哪

### 1.1 一句话

**旧指标把「用户后来又说了话」一律当成本，而其中 99% 是用户在提新需求、补充前提或回答 AI 自己的提问——不是纠正。于是一个「问得越准」的机制，指标只会更差。**

### 1.2 三处可指的代码

| # | 位置 | 它把什么算进了成本 | 后果 |
|---|---|---|---|
| ① | `measure-interventions.mjs:572`<br>`const iv = s.counts.interrupt + s.counts.answer + s.counts.interject + s.counts.correction + s.counts.nudge;` | **`answer`**——即 `AskUserQuestion` 的作答。判据在 `avoidabilityOf()` 第 297 行 `if (type === 'answer') return 'Q';`，Q 被记进 `interventions` | 「AI 问得越准、用户答得越多，介入总数越高」。`2026-11-13-critique-question-layer-product.md` §4.4 那条「把 P1 提前问掉会变成 Q，所以总数不降」的推导，**在它自己的口径下完全正确，而这个口径把提问当成了成本** |
| ② | `measure-execution-phase.mjs:382`（定义）、`:503`（输出 `execInterruptions: execHumans.length`） | 执行期**每一条**人类发言。它与①不同——它**已经不数作答**（作答是 `tool_result`，不是人类发言），但它把「再扫一下 D 盘」「按你建议来」「先做第 1 件」全算成中断 | 由此导出的「一次性完成率」(`oneShotRate()`，第 574 行) 实测是**在执行期一句话都没说**，不是「做对了」。见 §1.4 |
| ③ | `measure-execution-phase.mjs:543` `groupSessions()`；`measure-intervention-cost.mjs:405` 附近同款 | 只认 `askuserquestion` 一个工具名 | **`ExitPlanMode`（计划批准）不属于任何一组**。实测它有 14 次调用，其中 8 次拿到「User has approved your plan」——那是一次完整的「先确认再开工」，却被记成「从不提问」。实测有 **2 个会话**因此被错分进 C 组 |

### 1.3 成本到底是分子、分母，还是两者

- 在 `measure-interventions.mjs` 里，成本是**分子**（`iv`），分母是会话数 / 人类发言数 / AI 停止数（`rates`，第 619–621 行）。
- 在 `measure-execution-phase.mjs` 里，成本是**分子**（`execInterruptions`），体量是**另一列**（`execTools`），两者只在中位数与匹配里被放一起比。
- 在 `measure-intervention-cost.mjs` 里，成本是**分子与分母**：`返工需求率 = 返工需求 ÷ 中断`（`groupRow()`，第 583 行附近）。**分母本身是个成本量**——这就使「中断多了，率反而被稀释」成为可能。

三个脚本没有一个是「分子是纠正、分母是工作量」。本报告要改的正是这件事。

### 1.4 旧「一次性完成率」的实测：它数的是沙箱，不是成功

`--days 0` 实测（含沙箱）：**执行期零发言的 94 个会话里，92 个是本仓自己的 e2e 测试沙箱**（97.9%）。
那些会话的首条人类消息长这样：`"Create bq.txt containing HI. Then stop."`——它们的执行期工具是 0。

| 口径 | 旧「一次性完成率」 |
|---|---|
| 含沙箱（旧报告用的分母） | C 组 **68.6%** |
| 剔掉本仓测试沙箱 | C 组 **4.4%**（45 个里 2 个） |

**所以「C 组从不问，一次性完成率 31.4% / 68.6%」这个数不是「从不问更靠谱」，是「我们的测试沙箱不干活」。**
这一条**与提问时机无关**，是分母污染。它足以单独否掉那个数，不需要新指标出场。

## 二、新主指标的定义

### 2.1 一句话

> **执行期纠正密度 = 执行期内「用户纠正 AI」的人类发言条数 ÷ 执行期实际工作量 × 100**

### 2.2 逐项可判定

| 项 | 定义 | 落在代码里的位置 |
|---|---|---|
| **执行起点** | 第一次写操作的 `tool_use`。写操作 = `Write`/`Edit`/`NotebookEdit`/`MultiEdit`，或被 `verify-claims.isMutatingCommand` 判为改写工作区文件的 shell 命令。**完全复用**既有判据 | `isWriteCall()`（import） |
| **执行期** | 执行起点之后的一切记录 | `sessionRow()` |
| **分子：成本** | 执行期内、`classifyHumanMessage(text) === 'correction'` 的人类发言。**只有这一档** | `classifyExecHuman()` / `isCostly()` |
| **分子排除 a** | 会话首条人类消息（那是开工指令，不是介入） | `sessionRow()` |
| **分子排除 b** | `[Request interrupted by user]` 标记（宿主写的字，不是人打的） | `readAskTimeline()` |
| **分子排除 c** | `AskUserQuestion` / `ExitPlanMode` 的作答（`tool_result`，物理上不是人类发言） | `readAskTimeline()` |
| **分母：体量** | 执行期 `tool_use` 总数 **−** 执行期提问次数 | `sessionRow()` 的 `execWork` |
| **不计入成本** | 开工前的一切对话（含提问与作答）、`normal` 档发言（新需求 / 补前提 / 报告现象 / 问进展）、`nudge` 档（见二档） | `definitions.notCost` |
| **辅助（二值版）** | **无纠正完成率** = 执行期纠正为 0 的会话占比。它是对旧「一次性完成率」的最小改动：分子从「任何发言」换成「纠正」 | `cleanRate()` |
| **二档（敏感性）** | `correction + nudge`，同一分母。**不进主指标**：催促可以是用户自己的节奏选择 | `SECONDARY_TIERS` |

**分母为什么扣掉提问**：若把提问留在分母里，问得多的会话分母虚高、密度被稀释——那等于偷偷奖励多问，与「提问是投资」同样不相容。扣掉之后分母才是「实际干的活」。

**为什么分子不分「用户主动提新需求」与「用户纠正 AI」**：`classifyHumanMessage` 的判据就是「含否定/回退语义」（`CORRECTION` 正则，`measure-interventions.mjs:76`）。**只有含否定语义的那一档进分子，其余全进 `feedback`。** 这是本指标与旧指标的唯一分界线，也是它能机械判定的原因。

### 2.3 为什么它比旧指标对——用重算后的数说

同一份语料、同一次运行，把两个口径并排放（`--real-only`，剔掉本仓测试沙箱，n=85）：

| 组 | 旧：执行期中断次数 | 旧：一次性完成率 | **新：纠正密度（/100 工作）** | **新：无纠正完成率** |
|---|---|---|---|---|
| A 开工前问（n=7） | 14.4（既有报告） | 0.0% | **0.035** | **5/7 = 71.4%** |
| B 开工后问（n=33） | 30.5（既有报告） | 0.0% | **0.019** | **27/33 = 81.8%** |
| C 从不问（n=45） | 7.4（既有报告） | 4.4%（去沙箱前 68.6%） | **0.017** | **41/45 = 91.1%** |

三点用数说话：

1. **旧口径下 A 组「0% 一次性完成」，新口径下 71.4%。** 差的不是数据，是分子：旧分子数「说过话」，新分子数「被纠正」。A 组 7 个会话里 5 个一次纠正都没有，它们在旧口径下全部是「失败」。
2. **旧「一次性完成率」的 C 组优势 68.6% 去沙箱后塌到 4.4%。** 那不是提问时机的效应。
3. **新口径下 A 组仍然不是最好的**：0.035 高于 B 的 0.019 与 C 的 0.017；无纠正完成率 71.4% 也低于 B 与 C。**这条如实写，不为了决定好看而调口径。**

### 3.5 **新口径下 A 组是否仍更差：是**

必须原样写出：

- **纠正密度**：A 0.035 > B 0.019 > C 0.017。**A 最高。**
- **无纠正完成率**：A 71.4% < B 81.8% < C 91.1%。**A 最低。**
- **1:1 匹配**：A 纠正更少 0 对、更多 2 对、打平 3 对。**A 没有赢过任何一对。**
- **门槛 ≥400**：A 0.043 / B 0.019 / C 0.018。**A 更差，且差距最大。**

## 四、旧结论：哪条被推翻，哪条仍成立

这是本文最重要的一节。

### 4.3 一句话的总结

**换掉指标，改掉的只有一件事：「A 组 0% 一次性完成」这个吓人的数消失了（71.4%）。**
**「提前问在这里不更优」这一条活了下来。** 所以：用户「提问是投资」这个价值选择不再被指标惩罚，
但**仓库里没有任何数据可以说「提前问减少了纠正」**。这两件事必须同时说。

## 五、这个决定意味着什么不能再声称

- ❌ **不能再说「这套方法提高了效率」。** 新口径只能说「按这个定义，A 组并不更差/更好」——实际是**略差但不显著**。
- ❌ **不能再说「一次性完成率」是产品指标。** 去掉沙箱后它只剩 4.4%，且它数的是「有没有再说话」。
- ❌ **不能再说「提前问能减少返工」。** 新分子 19 个事件，A 组 2 个。方向甚至相反。
- ✅ **可以说**：「提问不计入成本」是一个**已被写进口径的价值选择**，不是被数据推翻的结论。
- ✅ **可以说**：旧口径下 A 组看起来失败，一部分是分母污染（92 个沙箱），一部分是分子定义（把新需求算成成本）。

## 六、我算不出来的（不许当结论用）

1. **「该不该纠正」没有 oracle。** 我能数用户说了几次「不对」，数不出「这次改动本来就该被推翻」。新口径只比旧口径**更接近**「返工」，没有解决这个问题。
2. **分子太稀疏。** `--real-only` 全语料 19 次纠正（占执行期发言 1811 的 1.05%），A 组 2 次、7 个会话。**任何 p 值在此样本量下都不可信**，包括我算出来的那些。
3. **召回率未知。** 只认含否定词的短消息（≤600 字符）。「再看看」「我觉得有点怪」数不到。**本指标是下界。**
4. **「作答是打字」的泄漏只有 17 条，其中纠正 0 条。** 因此新分子不受污染——但这是**当前快照**的事实，不是结构保证。脚本每次运行都重数这两个数，`humanAfterAskCorrections > 0` 时口径即失效。
5. **`ExitPlanMode` 实测 14 次工具调用：6 次是 `not in plan mode` 报错、7 次是真批准、1 次被用户拒绝。** 它不属于标准工作流，把它算作「提问」是为了不把 2 个会话错分进 C 组，**不表示「用计划批准」是常见做法**。另注：全文里「ExitPlanMode 19」是字符串命中数（含入参回显），**14 才是真实工具调用数**。
6. **沙箱判据有已知缺口**：POSIX 的 `/tmp` 不在 `SANDBOX_RE` 内（与 `observe-reality-check.isSandbox()` 同源，为的是分母能对话）。本机语料全在 Windows，此缺口不影响以上数字。测试 `isSandbox 的已知缺口` 把它钉住了。
7. **工作量口径覆盖哪些写操作？** `isWriteCall` 认 `isMutatingCommand`（既有判据），**所以工作量包含 shell 写入**。但 Bash 写入的路径无法可靠定位，因此它们不参与任何按路径的分析（本条无按路径分析）。
8. **fork / 恢复分支的成因仍然未知。** 两层去重都是经验判据，没有 oracle 能证明某一份文件该不该并。

## 七、给决策者的三行

```
① 旧指标把「提问的作答」（measure-interventions.mjs:572 的 answer）和「执行期的每一句话」
   （measure-execution-phase.mjs:503 的 execInterruptions）都当成本。实测：98.9% 的
   执行期发言不是纠正——成本桶里装的基本不是成本。

② 新主指标 = 执行期纠正密度（Σ纠正 ÷ Σ(执行期工具−执行期提问) × 100）。
   同一份语料 --real-only：A 0.035 / B 0.019 / C 0.017（n=7/33/45，p=0.41/0.56）。
   A 依然最差，1:1 匹配 0 胜 2 负 3 平，门槛 ≥400 差距最大。
   **「提前问在这里不更优」这一条活了下来——它不是指标问题。**

③ 被推翻的是旧「一次性完成率」：执行期零发言的 94 个会话里 92 个是本仓 e2e 沙箱
   （"Create bq.txt... Then stop."），去沙箱后 C 组从 68.6% 塌到 4.4%。
   新口径下 A 组是 71.4% 无纠正，不是旧的 0.0%。
```
