## 零、结论先行

**1. 「同时开 10+ 个会话」这个用户画像是假的，至少在这台机器上是假的。**
实测：把一个会话按「间隔 > 5 分钟」切成活跃段后重建全局并发曲线，**87.1% 的墙钟时间一个活跃会话都没有**；
在有会话活跃的时间里，**31.4% 只有 1 个**、17.5% 两个、13.2% 三个，≥5 个只占 **4.7%**。
按项目看更极端：**24 个项目里 16 个从未同时超过 1 个会话**，最高的一个（46 个会话）峰值是 **3**。
我们所有产品决策都建立在一个**在这台机器上不存在**的场景上。

**2. 真正的重复不是「会话之间打架」，是「同一个会话被复制了」。**
1,606 个文件被 ≥2 个会话改过；其中 86 对在 60 分钟内，**这 86 对全部能被 uuid 交集解释为同一个 transcript 的分叉**（同一组件占比 > 20%），
**独立会话之间的文件竞争是 0 例**。而分叉本身很贵：25 组会话共享完全相同的首条 prompt（158 个会话），
6 个会话被另一个会话**严格包含**（uuid 全包含），光这几对就重复了 **5.3M output token**。
`scan-sessions.mjs` 与 `verify-claims.mjs` 里都**没有任何分叉检测**（grep `continuedInSessionId` / `fork` / uuid 包含 = 0 命中）。
后果不是好看不好看：**同一个 transcript 被算两次，calls、tokens、断言数全部虚高**。

**3. 我们一直说「前台会话没有 token 计数」——这句话在这个宿主版本上是错的，而且错得很值钱。**
`docs/GUIDE.md:132` 原文：「只有能关联到后台作业的会话才有。**前台交互会话没有**：宿主不落盘它们的 token 计数」。
实测：253 个主 transcript 里 **181 个**带非零 `message.usage`，其中 **180 个关联不到任何 job**；
85 个会话额外带 `cost-state`，含 `totalCostUSD` 与按模型的 `outputTokens / cacheReadInputTokens / costUSD`。
全语料累计 **$18,325 USD**，单会话最高 **$2,499**，5 个会话超过 $1,100。
这不是「多一个字段」，这是一条**从未被读过的、以美元计价的账**。

**4. `SUPPORTED` 不等于「干得好」，而且这个洞可以量化。**
3,949 个 `tool_result.is_error`，**90.7% 在之后 8 条记录内没有任何 assistant 文本提到它**（138 个会话）。
含断言的 38 个会话，静默错误中位数 **26**；不含断言的 227 个，中位数 **0**。
25 个判 `SUPPORTED` 的会话里，**17 个的静默错误 ≥ 10**。
也就是说：我们的旗舰判据回答的是「这句话有没有证据」，**而用户真正在骂的是「你把 26 个报错吞了还说全绿」**。这两件事相关但不等价，而后者我们一个字都没测。

**5. 最被低估的一块现成能力：`~/.claude/file-history/` 是一份完整的 AI 文件版本库，我们从来没用过。**
12,057 个 blob / 165 MB / 2,085 个 fileId，内容就是**文件的全文**（我打开了一个确认是真实 markdown 与 Java 源码）。
通过 `file-history-delta` 记录里的 `backupFileName + realParentDir + trackingPath` 可以精确还原
「哪个会话、在第几版、把哪个路径改成了什么」。实测打通一条：
`scripts\oversight-tui.mjs` → `b787a6ef44d811df@v1`，38,941 字节，文件存在。
这是**不需要 git 的行级来源追溯**，也是唯一能让「这个文件是谁改的、什么时候、用什么模型」变成可回答问题的东西。

## 一、被忽略的使用场景

### 1.1 先把假设拆掉：现在假设的用户，行为痕迹长什么样

实测这台机器的真人行为（2,475 条 `origin.kind === 'human'` 的输入）：

| 指标 | 实测 | 含义 |
|---|---|---|
| 长度 ≤ 10 字符的输入占比 | **28.8%**（713 条） | 近三成是「继续」「做吧」「好」这种 |
| 同一会话内**逐字重复**的输入 | **14.1%**（349 条） | 同一句话被打了不止一遍 |
| 内容恰为 `Try again` / `再试一次` / `重试` | **108 条** | 纯重试 |
| 内容恰为「继续 / 接着 / 往下 / 开始吧」 | **85 条** | 纯推进 |
| 相邻两条真人消息的间隔 | p50 **4,340 s（72 分钟）**，52.6% > 1 小时，20% > 8 小时 | 这是「离开—回来」节奏，不是监控 |
| `AskUserQuestion` 被回答的延迟 | n=179，p50 **168 s**，p90 2,382 s，12 次 > 1 小时 | 人**在场**，看得见弹窗 |
| 入口分布 | `claude-desktop-3p` **224**、`cli` 9、`sdk-cli` 24、`claude-vscode` 6 | 主战场是**桌面 App**，不是终端 |

三个推论，每一个都和现在的产品形状相反：

- **推论 A**：痛点的形状不是「信息过载」，是「**重复劳动**」。近三成输入是两个字的推一下。
  用户不是看不过来，是**被要求把手放在键盘上 100 次**。
- **推论 B**：痛点的时机不是「实时监控」，是「**离开 72 分钟后回来对账**」。p50 间隔 72 分钟直接量出来了。
- **推论 C**：**我们的 TUI 是给一个用户几乎不用的入口做的。** 224/264 个会话从桌面 App 发起，
  我们把全部形态投入放在终端。

### 1.2 具体场景（不是「一般来说」）

| 角色 | 痛在哪（具体） | 现有工具为什么没解决 | 我们现成的能对上什么 |
|---|---|---|---|
| **团队 lead / 外包发包方** | 他要的不是「谁在跑」，是「**这笔钱买到了什么**」。$2,499 的会话产出 40,713 行，其中多少被留下来了？ | 宿主给的是过程；GitHub 给的是 diff；**没有任何工具把「成本 → 产出 → 断言 → 证据」串成一行**。市面上 agent 基建（agent 身份/支付/运行时治理）全部停在「谁在调」这一层，「活干成了没有」这一层空着 | `cost-state`（美元/模型/行数）+ `verify-claims`（断言/证据）+ `file-history`（行级来源）= **$/已核实交付** 这一列 |
| **运维 / SRE（非编码 agent）** | 他管的是 cron 里跑的 agent：告警归因、变更审计。「这个 bot 昨晚到底改了什么」 | 结构化日志（OTel GenAI semconv 还在往 Stable 推）要**应用自己埋点**；现成 agent 没埋 | `verify-claims` 的核心其实不是「AI 声明」，是「**任何一句可机读的断言 vs 支持它的调用**」。同样的代码三家都能用：告警 bot 说「已恢复」、迁移脚本说「已迁移 412 行」 |
| **研究员 / 复现性** | 论文要能复现。「这个 agent 在第 17 轮时工作区到底是什么样」 | 现在只有 transcript（对话），没有**文件快照** | `~/.claude/file-history/` 就是答案：12k 个版本化 blob，按会话分目录。**这是别人没有的** |
| **学生 / 招聘 / 作业** | 反过来的问题：「这份作业/这个 take-home 是 AI 做完的吗，它真的跑过测试吗」 | 检测 AI 文本的工具在猜；而**我们判的是行为**——有没有真的跑 `npm test`、跑在最后一次编辑之前还是之后 | `verify-claims` 的四档 + 「最后一次源码编辑之后有没有成功测试」这条时间线，是**现成的学术诚信/招聘评估判据**，而不是文本分类器 |
| **不同的 harness**（Codex / Gemini CLI / Cursor） | 每家的会话格式不同，谁都不愿意为别人的 harness 写观测 | 各写各的（`codeg` / `paseo` 是做聚合而非做判据） | 我们已经有 ACP 驱动能力 + 纯函数式证据层（`detectClaims` / `findEvidence` 只吃 records 数组）。**换 harness 只需要换 adapter，判据不用改** |

**一条实测到的行业信号，值得单列**：本机 `~/.codex/external_agent_session_imports.json` 里有 **17 条记录**，
`source_path` 直接指向 `~/.claude/projects/*.jsonl`，还带 `content_sha256`。
**另一个 harness 已经在做跨 harness 的会话摄入。** 我们不是唯一想到「跨 harness」的人，而且对方是产品化的。

## 二、被忽略的能力复用

### 2.1 `verify-claims` 真正的抽象层次：它不是「验 AI 的话」，是「**验任何一句可核对的断言**」

看它的三个纯函数在做什么：

```
detectClaims(text)          → 从自由文本里认出「可机器核对」的断言族（8 族 + 1 个不可核对族）
findEvidence(records, claim)→ 在调用轨迹里找「会支持/反驳它」的那一类动作
classifyEvidence(...)       → 用「最后一次变更」这条时间线把证据分成四档
```

**这四档里最值钱的不是 `SUPPORTED`，是 `STALE_ONLY`。** 它的语义是：
「你确实跑过测试，但你在那次测试**之后**又改了源码」。这条判据对任何「先验证、后改动」的工作流都成立：

- 承包商说「验收通过了」，但验收之后又动了交付物；
- 安全扫描说「无高危」，但扫描之后又合了 3 个 commit；
- 迁移脚本说「已迁移」，但迁移之后又跑了一次写入。

**「最后一次变更之后还有没有验证」是一个通用不变量**，与 AI 无关。现在的实现把它绑死在 transcript 的 tool_use 上，这是**只发挥了 20%**。

### 2.2 transcript 解析的另一种用法：**来源账本**

`file-history` 打通的是一条现在没有任何产品能回答的问题链：

```
这一行的作者是谁（哪个 session / 哪个 subagent / 哪个 model）
→ 它属于哪条断言
→ 那条断言有没有被证据支持
→ 那次运行花了多少钱
```

实测可行：`file-history-delta` 里有 `trackingPath` + `realParentDir` + `backupFileName` + `version` + `timestamp`，
blob 路径是 `~/.claude/file-history/<sessionId>/<fileId>@v<N>`，`fileId` 跨版本稳定。
**这意味着「按行的 AI 来源归属」是现成可算的**，成本是读 blob 的头部。

这条路要小心一个实测到的坑：我用 12 个 Overwatch 自己的文件做「磁盘现状 vs 最后一条 AI blob」比对，**12/12 都不相等**——
因为之后有人工编辑、有别的会话再改。所以它不是「校验磁盘」，用法必须是**「还原任意时刻」+「比两个 AI 版本」**，不是「比对当前」。

### 2.3 证据分级本身能不能是产品？

**能，但卖法和直觉相反。** `T0–T4`（断言 / 单次运行 / 独立事实核对 / 反向对照）这套东西的价值不是「我们更严谨」，
是它**可以变成别人必须回答的问卷**：

> 你的 agent 说「测试通过」——是 T1（它自己说的）还是 T3（有第三方能核对的输出）？

这东西对外的形态不是库，是**一份可以贴在 PR 模板 / 采购合同 / 审计清单里的评分表**。
它的变现路径不是软件，是**标准与信誉**；而标准要立得住，必须有一个**公开的、有人标注过的基准集**——见 §5。

**顺带一条诚实提醒**：现在的「84.6% 精度（n=13）」在任何对外场合都会被一句话打死。要做标准，先把 n 从 13 提到 200+。

## 三、被忽略的形态

| 形态 | 为什么可能更好 | 为什么可能更差 | 现有零件的距离 |
|---|---|---|---|
| **停机闸（Stop hook）** | 唯一**平台自己允许**的强制点：不是别的会话冒充用户点同意，是 agent 拦自己。宿主字符串里确实有 `Stop hook denied continuation` / `Stop hook prevented continuation` / `Stop hook blocking error from command`。而且宿主自带的 `/goal` 评估器**明确不能读文件**（原文：`evaluator verifies the condition from the conversation alone — it cannot run commands or read files`）——我们刚好能 | 精度不够就会在两周内被用户关掉。**84.6% 对一个每次拦截都可见的闸门来说是不可接受的低**。另外二进制里有 `Stop hook block discarded`，若它意味着宿主动辄丢弃 block，闸门就是装饰——**这条我必须标为未验证** | 极小。`verify-claims.mjs` 已经有退出码语义（1 = 有问题），hook 只要 `process.exit(2)` + 把 `--format md` 的输出塞回 stderr |
| **静态 HTML 报告** | lead / 审计要的是「一份可以转发的东西」，不是「一个要装的工具」。$18k 的账 + 断言核对 + 未通过项，做成单文件 HTML 就是交付物 | 只读、不改变行为。属于「看一眼就归档」的形态 | 小。`--json` 已经有了 |
| **CI / PR 检查** | 逻辑上最顺（exit code 已经是 0/1/2） | **但它验的是 transcript，而 CI 里没有 transcript**。要把它搬进 CI，必须先把断言从「对话」改写成「PR 描述里的声明」——那是另一个产品 | 中。需要一个新的 claim 来源 adapter |
| **编辑器插件** | 用户在场时最省事 | 数据不在编辑器里。编辑器能看到的只有当前文件，看不到「上次会话的断言」。**形态和数据源不匹配** | 大，且方向不对 |
| **API / SDK（ACP client）** | 「外包给外部 harness」这件事的正确落点 | 协议层已经被别人做完（OpenHands 的 ACP 会话、`acpx`），差异化只能在**判据**上，不能在驱动上 | 中。`2026-11-04-external-harness-protocols.md` 已实测通 |

| **凭证/卫生扫描** | **一条命令就能让人装**：「你的 251 个会话日志里有 3 个 GitHub PAT、1 个 `sk-`、908 处口令形态」。这是可验证的、吓人的、零争议的 | 与主叙事无关，容易被当成一次性小工具 | **极小**。我们已经在读这些文件了 |

## 四、反向：如果根本假设是错的

三个候选，按我认为的可能性排序。

### 4.1 最可能错的一条：「用户要的是看得更清楚」

实测反对证据：

- 28.8% 的输入 ≤ 10 字符；14.1% 是同一句话的重复；108 条 `Try again`；85 条「继续」。
- 相邻真人消息间隔 p50 **72 分钟**——人不在看。
- `AskUserQuestion` 的回答延迟 p50 **168 秒**——人**看得见**，弹窗问题基本被解决了。

**如果这三个数字成立，那么「可见性」这条需求的边际价值已经接近零，而「少按一次键」的边际价值还很高。**
用户不是被信息淹没，是被要求**反复确认同一个已经知道的事**。

→ 若这条成立，正确的产品不是更好的仪表盘，是**更短的确认路径**：把「继续」「重试」「看过了」变成一次按键甚至零次。
这也解释了我们为什么做 TUI 越做越复杂却没人用：**我们在优化一个用户已经不缺的东西**。

### 4.2 第二条：「完成声明的真实性用户在乎」

反对证据：断言之后的下一条真人回复里，含反驳词（还是/没有/失败/不对/…)的占 **16.1%**（752 对），
按 `verify-claims` 自己的判定分组：`SUPPORTED` 的 11 条里只有 **1** 条被反驳。
也就是说 **约 84% 的「做完了」用户是接受的**。

**这是对旗舰功能最不客气的一刀**：如果 84% 的断言根本没人质疑，那么逐条核对的期望收益是低的——
除非那 16% 的代价极高。而确实有证据支持「代价极高」：全语料 10 个会话里出现了明确的
「谎报军情」「纯谎报军情」「美化 README」这类指控，其中一条是「我等了好一会才出现弹窗，然后它报了个假的完成」。

→ 所以正确的表述不是「用户在乎真实性」，是：**这是一个高严重度、低频率的问题**。
高严重度低频率的东西**不适合做日活工具**，适合做**闸门**（每次都必须过，但平时不打扰）。这直接决定了 §5 的赌注形态。

### 4.3 第三条：「单位是会话」

实测：**4,864 个子 agent transcript = 7.86 GB，主 transcript 只有 1.82 GB——81% 的字节在子 agent 里。**
而 `scan-sessions.mjs` 的行源是主 transcript，子 agent 只作为一个计数与派生树的装饰。
`verify-claims` 默认**不读**子 agent（要 `--include-subagents`）。

→ 「公司」这个比喻里，**员工是子 agent，不是会话**。我们现在的表是「部门列表」，不是「工单列表」。
而且子 agent transcript 里**带完整 usage 与 model 字段**（3,306 个里 3,299 个有），
所以「哪个员工、用哪个模型、花了多少」是可算的——**这就是账本的地基，而我们连楼都没盖**。

## 五、一个具体的赌注

### 赌注：**把证据核对做成「停机闸」，而不是「审计报告」**

**一句话**：agent 每次准备停下来声称完成时，`verify-claims` 以 Stop hook 的身份跑一遍；证据不足就让这轮**不许停**，
并把「你说测试通过，但最后一次源码编辑在 10-19 01:35，之后没有任何测试调用」这句原话回灌给它。

**为什么是这一个**（四条，都可反驳）：

1. **它是这个平台上唯一合法的强制点。** 我们花了整个项目证明「往用户眼前的会话注入」被安全模型堵死；
   而 hook 是 agent 拦自己，平台不但允许，还内置了这套协议（`Stop hook denied continuation` 就在 2.1.308 的二进制里）。
   **从「求用户按一下」变成「机器自己过一遍」，这是这条产品线上唯一一次真正的杠杆变化。**
2. **它顺手补齐了宿主的洞。** 宿主自带 `/goal` + 独立评估器，但评估器字面写着
   `verifies the condition from the conversation alone — it cannot run commands or read files`。
   **我们能读文件、能读 tool_result、能判时间线**。这是「宿主做不到而我们做得到」，不是「宿主做了我们去追」。
3. **它自己产生标注数据。** 每一次拦截都会得到一个可见的对错（用户要么放行要么骂）。
   这正好补上 README 里那条已知局限「通知抑制准确率无法自测——需要人标注，没有基准」。
   **闸门本身就是标注流水线。**
4. **它跨 harness 可移植且不需要新用户画像。** 现在的用户就在用 CC，不用装、不用改工作流。

**它失败的条件**（预先声明，事后不许改）：

| # | 失败条件 | 怎么测 |
|---|---|---|
| F1 | **分族精度不够**。总精度 84.6% 意味着每 6 次拦截有 1 次是错的，两周内一定被关掉。**必须先测「哪一族精度 ≥ 97%」，只对那一族开闸，其余只警告不阻断。** | 对 8 个断言族各标 ≥ 40 条，逐族算精度。**没测之前不许开闸** |
| F2 | 宿主的 block 可以被丢弃。二进制里有 `Stop hook block discarded` 这个字符串；若它意味着宿主在常见情况下静默忽略 block，闸门就是装饰 | 写一个一定 block 的 hook，跑 20 次，数实际被拦下的次数。**这是 T4 反向对照，必须先做** |
| F3 | 回灌文本把会话带偏。我们看到 90.7% 的 tool 错误从不被提及，说明 agent 对反馈的注意力本来就差；再塞一段告警进去可能只是烧 token | 对比开闸/关闸两组会话的「断言后被人反驳率」与 token 消耗 |
| F4 | 宿主把 `/goal` 的评估器升级成能读文件 | 每个宿主版本 diff 一次二进制里那两句字符串 |

**如果只能保留一个数字来衡量成败**：**「断言后被人反驳的比率」从 16.1% 降到 8% 以下**。
不是拦截次数，不是精度——是**最终用户还骂不骂**。

## 六、本报告最容易被推翻的地方

1. **n=1。** 所有并发、成本、行为数字都来自一台机器、一个用户、约 5 个月。
   「10+ 会话」可能是**别人的真实画像**，只是不是这个用户的。若要对标，必须再找 5 台机器。
2. **「活跃」的操作化有偏。** 我把会话按 gap > 5 分钟切活跃段。一个会话卡在权限提示上是「不活跃」的——
   于是并发被**系统性低估**。这条对 §0 结论 1 是反向的，必须记住。
3. **静默错误 90.7% 这个数字里混了「正常的非致命错误」**（比如 `grep` 没匹配到、`ls` 目录不存在）。
   我没有区分「错误」和「预期内的非零退出」。要把它做成指标，**必须先建一个错误分类**，否则就是新一轮噪声桶。
4. **分叉判定用的是 uuid 交集启发式**（阈值 20%）。「86 对全部是分叉」这个结论依赖这个阈值，
   我**没有**用 `continuedInSessionId` 交叉验证（全语料里那个字段本来就几乎不出现）。
5. **`$18,325` 是 85 个会话的 `cost-state` 之和**，不等于用户真实账单：缓存计价、订阅额度、第三方网关都不在内。
   而且 `cost-state` 的 `modelUsage.outputTokens` 与我自己从 `message.usage` 累加的值**不相等**
   （例：`50ec242b` 分别为 6.14M 与 3.02M，差 2 倍）。**两个数字打架，我没有查清为什么**——
   这是我要诚实标注的一处未解矛盾，也是 §1.2 里「$/已核实交付」这个指标落地前必须先解决的问题。
